[size=4][b]Interrupt Package Deadlock Fix[/b][/size]
Fixes a vanilla engine [b]freeze[/b] (a deadlock) in Skyrim Anniversary Edition [b]1.6.1170[/b]. It has mostly been seen with a follower in combat.

[b]Public beta:[/b] the freeze and the fix were both traced with a debugger in a real game, but the fix needs more play-testing on more setups. Reports are very welcome. See Troubleshooting below.

[size=3][b]The freeze[/b][/size]
While the game updates NPC AI on a background thread, it holds a "read" lock on the player's data. In two places it then cancels an NPC's [i]interrupt package[/i] (the short behaviour an NPC switches to when something interrupts them) without letting go of that lock.

Cancelling it can need to [i]write[/i] the player's data, and a write has to wait until every reader has finished, including the very thread that is waiting. That thread waits on itself, the main thread waits on it, and the game freezes. The picture stops, the sound may loop, and only Task Manager gets you out. There is no crash log, because nothing crashed.

[size=3][b]The fix[/b][/size]
Those two calls are redirected. The NPC's interrupt package is cancelled a moment later (usually within a frame) on the main thread, once the lock has been released. The NPC is kept safely in memory until then. Nothing else in the game is changed.

[size=3][b]Safety[/b][/size]
[list]
[*]It only runs on Skyrim [b]1.6.1170[/b]. On any other version it does nothing and says so in its log.
[*]Both patched spots are checked byte for byte before anything is changed. If either isn't exactly what's expected (for example, another mod changed it), [b]neither[/b] is patched and the log says why.
[*]Nothing is written to your save. It can be added or removed at any time.
[*]No ESP, no MCM, no configuration.
[/list]

[/list]

[size=3][b]Installation[/b][/size]
[b]Mod Organizer 2:[/b] Install a new mod from archive, enable it, and launch through SKSE.
[b]Vortex:[/b] drag the archive onto the Mods page, enable, deploy, and launch through SKSE.
[b]By hand:[/b] copy [i]SKSE\Plugins\InterruptPackageDeadlockFix.dll[/i] into [i]Data\SKSE\Plugins[/i].

[size=3][b]Known limitations[/b][/size]
[list]
[*]The NPC's interrupt package ends about a frame later than in vanilla. No visible effect has been seen, but it isn't exactly vanilla timing.
[*]If another mod patches the same two spots first, this one stands down (it's logged). No such mod is known.
[*]This fixes one specific freeze. Other freezes have other causes.
[/list]

[size=3][b]Compatibility[/b][/size]
Works alongside other freeze and crash fixes that don't touch the same code. The author runs it with Skyrim Freeze Fix NG, which fixes a different freeze. Load order doesn't matter.

[size=3][b]Troubleshooting[/b][/size]
Log: [code]Documents\My Games\Skyrim Special Edition\SKSE\InterruptPackageDeadlockFix.log[/code]
[list]
[*][i]installed at ...[/i] twice: working.
[*][i]deferred EndInterruptPackage #N ...[/i]: the fix stepped in (shown for the first 20 times, then every 100th).
[*][i]not installed: ...[/i]: the line says why (wrong game version, or another mod patched the same spot). Nothing was changed.
[*]No log at all: check [i]skse64.log[/i] in the same folder for "InterruptPackageDeadlockFix".
[/list]
If the game still freezes with this installed, please post both logs and your mod list. If you can, also make a memory dump of the frozen game: Task Manager, right-click SkyrimSE.exe, "Create memory dump file".
